# CreatorOS — External Validation Protocol

**Status: planned. No external interviews, beta results or adoption claimed.**

## First cycle

Recruit five creators who publish actively and manage or seek multiple revenue
streams. This is an exploratory sample, not representative market research.
Record participant consent and use anonymous IDs in the public repository.

Before demonstrating the app, ask about the last real occasion they reviewed
performance or chose their next growth/revenue action. Capture their current
tools, workaround, frequency and consequence. Separate observed behaviour from
opinions or hypothetical willingness to pay.

Select one problem supported by those examples. Record the options considered,
chosen scope, trade-off and an observable success criterion before beta testing.

Give participants one task: enter a minimal portfolio, generate guidance and
select a next action. Record unaided completion, where help was needed,
incorrect personalisation, useful recommendations and actual follow-through.
Agree a follow-up window to observe return use. Do not require real financial
credentials to evaluate the initial workflow.

## Release and improvement record

For each cycle record: release date, commit/version, invited participants,
task, success criterion, number attempted/completed, help required, observed
issue, chosen change, and retest result. Link screenshots or consented,
anonymised notes when available. Keep raw identities and personal business data
private. Record zero/negative results and non-returning participants too.

Only after this evidence exists should the resume mention participant counts,
task-success changes or repeat usage. A proposed experiment is not an outcome.
